# AGENTS.md

Guidance for AI coding agents working in this repository. Humans: start with [README.md](README.md).

## What this is
The server is one Go binary that implements the OpenSandbox lifecycle API on Kubernetes (agent-sandbox warm pools +
gVisor), proxies the in-sandbox execd API, and persists `/workspace` to S3-compatible storage. Design and the
reasons behind it: [docs/architecture.md](docs/architecture.md) (decisions D1–D15). Read the relevant decision before
changing behaviour it covers.

## Layout
- `cmd/sandbox`: server (`sandbox serve`) and operator CLI (`sandbox admin ...`); configured only by env vars (docs/operations.md §3).
- `cmd/sandbox-snap`: static helper injected into every sandbox (pack/upload/hydrate snapshots, preStop guard).
- `internal/api`: HTTP routes, API-key auth, proxy to execd. Must stay compatible with the unmodified OpenSandbox SDKs.
- `internal/lifecycle`: state machine (create/pause/resume/delete), expiry, reconciliation, pod-interruption handling.
- `internal/cell`: the **only** package that knows sandboxes are Kubernetes pods (templates, warm pools, claims,
  NetworkPolicy, pod watch). Keep Kubernetes types out of other packages.
- `internal/store`: Postgres. `schema.sql` is embedded in the binary and applied idempotently at startup.
- `deploy/kind`, `bakeoff/`: local cluster setup and benchmarks. `tests/e2e`: SDK contract and interruption tests.

## Build and test
```bash
make test                         # go vet + unit tests; must pass before you finish
gofmt -l cmd internal             # must print nothing
make deploy                       # build image, kind load, apply (needs the kind cluster from bakeoff/)
```
- Postgres integration tests run only with `TEST_DATABASE_URL` (see `internal/store/store_test.go`).
- E2E tests need a running cluster, a port-forward and `SANDBOX_DOMAIN` / `SANDBOX_API_KEY`.
  `tests/e2e/interruption.py` **stops a cluster node**: never run it unless asked.

## Rules
- **State changes go through `store.Transition`** (compare-and-set on the current state). Never write `state` directly;
  never allow two pods for one sandbox (D6).
- **The pod template is the security boundary.** Don't weaken gVisor, non-root, dropped capabilities, the missing
  service-account token or the baseline NetworkPolicy. `internal/cell/cell_test.go` locks these; extend it, don't relax it.
  When the pod template changes, bump `templateRev` in `cell.go`.
- **No credentials in sandboxes.** Object storage is reached only through presigned URLs; the caller's API key is
  stripped by the proxy.
- **Never commit secrets.** Kind credentials are generated by `deploy/kind/secrets.sh`; local values live in gitignored
  files (`bakeoff/.local-secrets`). Don't print API keys or tokens in output or docs.
- **API compatibility:** responses must keep the fields the SDKs require (`internal/api/api_test.go`). Unsupported
  request fields should be rejected with 400, not silently ignored.
- Add a unit test with every behaviour change; record cluster-level results in `docs/validation.md`.
- Keep docs in sync: config → `docs/operations.md`, decisions → `docs/architecture.md`, plans → `docs/roadmap.md`, OpenSandbox endpoint support → `docs/api-coverage.md`.
